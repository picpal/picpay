# WAS OOM on EC2-A (t3.micro 1GB RAM)

## 발생 시점
2026-05-30 CD run 26685949742 실패 후

## 증상
- `kex_exchange_identification: read: Connection reset by peer` (GitHub Actions SSH 연결 실패)
- 로컬에서도 `Connection timed out during banner exchange`
- EC2 인스턴스 상태는 running이고 포트 22는 열려 있으나 SSH 데몬 무응답

## 원인
EC2-A (t3.micro, 1GB RAM)에서 Spring Boot 컨테이너들이 OOM kill 무한 루프:

```
[ 1962.652849] Memory cgroup out of memory: Killed process 46994 (java) total-vm:1710604kB, anon-rss:151100kB, file-rss:8136kB
[ 1976.837741] Memory cgroup out of memory: Killed process 47417 (java) total-vm:1781348kB, anon-rss:201776kB
...
```

### 구조적 문제
- EC2-A 사용 가능 메모리: 940MB
- 컨테이너 메모리 한도 합계: gateway(200m) + payment(256m) + billing(200m) + token(200m) + notification(150m) = **1006MB**
- OS + Docker daemon: ~300MB
- 총 필요: ~1300MB >> 940MB

### 트리거
CD 배포 시 **기존 컨테이너가 실행 중인 상태**에서 새 이미지를 load하고 새 컨테이너를 시작하면, 구 컨테이너 + 신 컨테이너가 동시에 메모리를 점유하여 OOM 폭발.

`restart: unless-stopped` 정책으로 인해 OOM kill → 재시작 → OOM kill 루프.

## 해결

### 1. EC2-A에 swap 2GB 추가 (영속)
```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### 2. NAT iptables 영속화 (stop+start 후 유실 방지)
```bash
sudo DEBIAN_FRONTEND=noninteractive apt-get install -y iptables-persistent
sudo netfilter-persistent save
```

### 3. cd.yml 수정 — 배포 전 기존 컨테이너 중지
기존 코드 (`docker system prune -f`만 하던 것)를 수정:
```yaml
echo "Stopping old containers to free memory before loading new images..."
docker compose -f /home/ubuntu/docker-compose.yml down 2>/dev/null || \
  docker stop $(docker ps -q) 2>/dev/null || true
docker system prune -f
# 그 다음 새 이미지 load + compose up
```

## 결과
- EC2-A 메모리: 940MB + 2GB swap = 충분한 여유 확보
- 배포 시 구 컨테이너 먼저 종료 → 메모리 spike 방지
- iptables 영속화 → stop+start 후에도 EC2-B NAT 유지
- EC2_HOST GitHub Secret 업데이트: 52.78.109.253 → 3.36.65.28
